# 实验报告：LAB-DET-020 编码变体与规则绕过

## 文档控制

| 项 | 值 |
|---|---|
| 编号 | LAB-DET-020 |
| 日期 | 2026-10-24 |
| 执行 | lead（AI） |
| 分类 | 检测工程 / 对抗测试 |
| 风险级别 | 低 |
| 状态 | 完成 |

## 1. 目标

用编码变体测 SQLi/XSS 规则，找出可绕过形式并补规则。

## 2. 范围与环境

- 样本：5 行合成日志（正常编码 SQLi、双重编码 SQLi、编码 XSS、大小写混合 XSS、HTML 实体 XSS）；
- 脚本：detect_web_sqli.mjs、detect_web_xss.mjs；
- 规则：sql-injection-web.yml、xss-web.yml。

## 3. 假设

H1：单层编码能命中；H2：双重编码/实体编码会漏。

## 4. 步骤

1. 构造 5 行变体；
2. 先跑原规则，记录 miss；
3. 补双重编码与 HTML 实体模式；
4. 重跑。

## 5. 结果

| 规则 | 补前 | 补后 |
|---|---|---|
| SQLi | 1/5（双重编码漏） | 2/5 |
| XSS | 2/5（实体编码漏） | 3/5 |

## 6. 证据

- 证据文件：data/security/experiments/LAB-DET-020/evidence.txt；
- 日志：data/security/detections/evasion-web.log；
- 修复：SQLi 加双重编码模式，XSS 加 HTML 实体模式。

## 7. 分析

事实：补规则后两条漏报能命中；未覆盖的变体仍存在。推断：编码对抗是长期猫鼠，规则只能覆盖已知形式。

## 8. 风险与影响

多层编码、注释混淆、Unicode 变体仍会漏；误报可能随模式增加。

## 9. 修复与后续

- 在采集侧先做规范化/解码再匹配；
- 建变体测试集；
- 未解决：未做多层编码穷举。

## 10. 结论

通过：双重编码与 HTML 实体漏报已修，规则覆盖率提升。
