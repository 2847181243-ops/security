# 实验报告验收清单

每份报告发布/入库前过一遍；结构检查用 accept_reports.mjs，内容检查由独立 reviewer 做。

## 结构（脚本自动）

- 标题、文档控制、目标、范围与环境、假设、步骤、结果、证据、分析、风险与影响、修复与后续、结论，缺一不可；
- 状态写清完成/部分完成/失败/受限；
- 证据段不能空，至少有一条命令输出、文件路径或日志；
- 不允许 TODO/待补/占位；
- 结论必须是四选一，不写“应该没问题”。

## 内容（人工/独立 reviewer）

- 范围：目标、版本、网络、权限写清；
- 可复现：命令能照着跑，参数完整；
- 证据：报告里的数字/输出与证据文件一致；
- 推断：标“推断”，不冒充实测；
- 状态：没验证的写“未验证/未测”，不写成通过；
- 脱敏：无内网 IP、口令、token、真实路径；
- 交叉：报告、卡、检测规则三处编号和结论一致。

## 结论

PASS / WARN / FAIL；FAIL 必须指出文件与行号，并要求重做或补证。
