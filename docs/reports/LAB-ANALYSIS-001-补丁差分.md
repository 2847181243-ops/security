## 1. 目标

从 Apache 官方 CHANGES 反推 41773/42013 的根因与修复边界，不做新利用。

## 2. 范围与环境

- 官方 CHANGES_2.4.50、CHANGES_2.4.51（archive.apache.org）；
- 本地复现记录 LAB-HIGH-001 与 42013 失败记录；
- 只读分析。

## 3. 假设

H1：41773 根因是 2.4.49 的路径规范化改动；H2：42013 是同一处修复不完整。

## 4. 步骤

1. 读 2.4.50/2.4.51 CHANGES 的安全条目；
2. 对照本地 41773 成功与 42013 失败记录；
3. 归纳根因、修复边界、检测含义。

## 5. 结果

| 版本 | 官方描述 | 本地结果 |
|---|---|---|
| 2.4.49 | 路径规范化改动导致穿越/文件泄露 | 41773 穿越成功；CGI 开启时 RCE |
| 2.4.50 | 修复 41773 | 默认配置下 42013 尝试 403/500 |
| 2.4.51 | 42013：41773 修复不完整；新增 ap_unescape_url_ex() 解码控制 | 未测 |

## 6. 证据

- 证据文件：data/security/experiments/LAB-ANALYSIS-001/evidence.txt；
- 原始 CHANGES：data/security/CHANGES_2.4.50、CHANGES_2.4.51；
- 本地报告：LAB-HIGH-001；42013 失败记录见 data/daily/2026-10-24.md（尝试段）与计划进度。

## 7. 分析

事实：官方明确 41773 是 2.4.49 路径规范化改动，42013 是 2.4.50 修复不完整，2.4.51 引入解码控制。推断：根因在“解码与规范化顺序/次数”，检测要覆盖多次编码，而不是只匹配 .%2e。

## 8. 风险与影响

把 2.4.50 当安全版本会留窗口；升级要到 2.4.51+。

## 9. 修复与后续

- 升级 2.4.51+；关闭不必要 CGI；Require all denied；
- 检测：双编码/混合编码路径；
- 未解决：未在 2.4.50 配出可用 42013 环境。

## 10. 结论

通过：补丁差分确认 41773/42013 的根因与修复边界。
