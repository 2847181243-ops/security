# 攻防演练 Playbook

## 0. 前置

- 目标只在隔离网络（labnet），不接公网；
- 开打前恢复快照；记录起始时间、快照名；
- 明确授权范围：只打本实验室 VM。

## 1. 侦察

- 端口：从攻击机扫目标常见端口，记录开放端口与 banner；
- Web：访问首页、登录页，记录 Server 头、框架、版本；
- 资产：列出域名/IP/端口/组件版本，形成攻击面表。

## 2. 验证

- 每个候选漏洞先做最小验证（单请求、单参数）；
- 带 CSRF token 的表单要把 token 一起提交；
- 只验证到“能证明”为止，不做破坏性操作（删除、加密、横向）。

## 3. 取证

- 保存请求/响应、命令输出、时间戳；
- 训练靶场标注“本地靶场，非真实产品”；
- 不贴完整利用链到公开渠道。

## 4. 检测

- 为每个攻击动作写一条检测假设（日志字段/进程关系/命令行）；
- 用合成样本先验证规则，再接真实日志；
- 记录误报与漏报条件。

## 5. 报告

- 用 `docs/reports/_模板.md`；
- 写清范围、步骤、证据、影响、修复、置信度；
- 未验证的利用写成“未验证”，不写成结论。

## 6. 收尾

- 恢复快照，确认靶场回到基线；
- 更新报告索引；
- 把踩坑写进 procedures。

## 附：host-only 管理网卡

- 两块网卡都在 169.254/16 时，回复会走错接口；给管理网卡加更具体的 /24 路由即可：
  `ip route add 169.254.78.0/24 dev enp0s8`
- 之后可用 SSH 直接取 `docker logs`，做真实日志检测验证。
